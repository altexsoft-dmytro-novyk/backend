# People Management Backend

Grown from a NestJS starter into the people-management API (frontend lives in `../frontend`). Per-area conventions live in `.claude/rules/` and load automatically when working with matching files.

## Tech Stack

- **Framework**: NestJS 11 (Express, CommonJS), TypeScript full strict
- **Database**: PostgreSQL 18 in docker-compose (DB only; the app runs locally)
- **Dev services**: docker-compose also carries LocalStack (S3) and Mailpit (magic-link mail catcher, UI on 8025)
- **ORM**: Prisma 7 (`prisma migrate`) with driver adapter `@prisma/adapter-pg`
- **Config**: `@nestjs/config` + Joi env validation
- **Validation**: global `ValidationPipe` (whitelist, transform) + class-validator
- **Docs**: Swagger at `/api/docs`; health via `@nestjs/terminus` at `/api/v1/health`
- **Tests**: Jest — unit in `__tests__/` folders next to their source, e2e in `test/` (e2e specs for a bounded context live under `test/<context-name>/`)
- **Contracts**: Pact provider verification against the frontend's recorded pact (`test/contract/`, own Jest project)
- **Measurement**: P6 and ACM9 performance suites under `test/measurement/`, each with its own Jest config

## Commands

- `nvm use` — REQUIRED first: project needs Node >=24 (`.nvmrc`)
- `npm run start:dev` — dev server with watch (port 3001)
- `npm run build` / `npm run lint` — build / ESLint
- `npm test` / `npm run test:e2e` — unit / e2e (e2e needs Postgres: `npm run db:up`)
- `npm run test:contract` — Pact provider verification (needs Postgres)
- `npm run measure:access-control:p6` — P6 timings (measurement only, asserts nothing)
- `npm run measure:access-control:acm9 -- --role baseline` — ACM9 NFR; this one can fail on a budget breach
- `npm run db:up|db:down` — the whole compose stack (Postgres + LocalStack + Mailpit), not just the DB
- `npm run db:migrate` (dev) / `db:deploy` (prod) / `db:studio` — Prisma
- `npm run create:root` — seed plus `db:bootstrap:access-control`; the access-control entrypoint for a fresh DB
- New feature scaffold: `nest g resource modules/<name> --no-spec` — legacy pattern, superseded (see Project Structure below); do not use it for a new bounded context

## Project Structure (`src/`)

- `main.ts` — bootstrap: `/api` prefix, URI versioning `/v1`, CORS, global pipe, Swagger
- `app.module.ts` — root module: imports only, no controllers/services
- `config/` — infrastructure: Joi env validation schema
- `prisma/` — infrastructure: global PrismaModule + PrismaService
- `common/` — cross-context `dtos/` and `logging/`
- `modules/` — pre-bounded-context placeholder scaffolding (`health`); not the pattern for new features
- **Bounded contexts** (canonical for new features, e.g. `user-management/`): each is its own top-level `src/<context-name>/` directory laid out as `application/{actions,controllers,dtos}`, `domain/{entities,interfaces,services}`, `infrastructure/{*.repository.ts,*.adapter.ts}` — see `docs/architecture/domain-driven-design.md` for the binding layout and dependency rules (`domain/` imports nothing from Prisma/NestJS transport/HTTP). `modules/users` (email/name placeholder CRUD) was replaced by `user-management/` as the first such context. Live contexts today: `access-control/`, `user-management/`, `storage/`.
- `generated/` — Prisma client output (gitignored, regenerated by postinstall)

## Code Style (universal)

- TypeScript full strict is ON — declare DTO/entity fields with `!` (they are instantiated by ValidationPipe/serialization, not constructors)
- All code comments in English
- Routes are versioned automatically: controllers get `/api/v1/...` from main.ts — never hardcode the prefix

## Environment

- App port **3001**; CORS is open for `http://localhost:4200` (the react frontend)
- `.env` is gitignored; `.env.example` is the committed template

## Gotchas

- Jest scripts carry `NODE_OPTIONS=--experimental-vm-modules` — required by Prisma 7's WASM client, do not remove
- Import supertest as default: `import request from 'supertest'` (esModuleInterop; namespace import is not callable)
- PG18 docker image mounts data at `/var/lib/postgresql` (NOT `.../data` as in PG<=17)
- Prisma 7: datasource `url` lives in `prisma.config.ts`, not in `schema.prisma`
