# Prisma Conventions

## Schema (`prisma/schema.prisma`)

- Models map to snake_case tables via `@@map("users")`
- Datasource `url` is NOT in the schema — it lives in `prisma.config.ts` (Prisma 7 requirement)
- Do not touch the generator block: `provider = "prisma-client"`, `output = "../src/generated/prisma"`, `moduleFormat = "cjs"` (NestJS is CommonJS — ESM output breaks the build)

## Migrations workflow

1. Edit `schema.prisma`
2. `npm run db:migrate` — creates + applies a migration (dev, prompts for a name)
3. Commit the generated `prisma/migrations/**` — never edit applied migrations by hand
4. Production applies with `npm run db:deploy`

## Access layer (`src/prisma/`)

- `PrismaService extends PrismaClient` with `PrismaPg` adapter (connection string via `ConfigService`) — the ONLY place that touches the DB connection
- `PrismaModule` is `@Global()` — feature modules just inject `PrismaService`, no imports
- Import client types from `src/generated/prisma/client`: model types (`User`) and the `Prisma` namespace (`Prisma.PrismaClientKnownRequestError`)
- `src/generated/` is gitignored and regenerated by `postinstall` (`prisma generate`)
